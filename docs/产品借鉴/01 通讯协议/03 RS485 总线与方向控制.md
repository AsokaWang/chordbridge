# RS485 总线与方向控制借鉴

核查日期：2026-10-24。本文为 GitHub 与官方资料研究，不是代码实现或硬件实测。

.NET 是用户已确认的实现方向；下述具体库和设计仍是候选建议。Windows x64、Linux x64、Linux ARM64、Windows ARM64 必须逐项验证，不能由“.NET Standard”推导出驱动和全部功能已经兼容。

## 结论

RS485 是差分电气接口，既可承载 Modbus RTU，也可承载泵、秤、报警器的私有协议。两线半双工与四线方案需要分别识别。**调度资源应该是物理总线或端口，不是每一个逻辑设备。**[接口依据](https://www.analog.com/en/resources/technical-articles/rs485-eiatia485-differential-data-transmission-system-basics.html)

## 建议设计

1. 一个物理端口只有一个收发调度器；不同站号、不同定时组都提交事务，不能各自打开同一串口。
2. 设备实例保存站号和协议绑定，物理连接保存波特率等总线公共参数；不允许实例偷偷改公共连接参数。
3. 明确自动方向控制、驱动支持的方向控制或需要 RTS 的厂商方案。标准串口 RTS 开关不等于所有平台均实现可靠 RS485 发送使能。
4. “已写入系统缓冲”不等于最后一个字节已经离开线路。发送后转接收的时序必须按驱动/适配器验证，不使用一个对所有设备通用的固定等待值。
5. 无事务 ID 的协议中，中断后迟到响应不可完美消歧。恢复可采用有界静默等待、协议校验或重开连接等策略，但不得宣传为物理撤销。
6. 对没有地址字段的私有协议，不假设能够在一条总线上自动区分多台设备。

## 与 Modbus 的边界

串口库只提供字节通道，不提供 Modbus 功能码和寄存器语义。Modbus RTU 的 CRC、异常码和串行事务规则应采用专用协议库，详见 [Modbus RTU](05%20Modbus%20RTU%20寄存器与事务.md)。其他私有协议由可视化规则或脚本实现。

## 未覆盖与风险

电气终端、偏置、隔离、共地和总线拓扑不能通过 GitHub 库解决。不能把 RS485 等同于以太网，也不能把多个 500 ms 任务理解为允许同时在两线上发送。Windows/Linux ARM64 均要验证硬件驱动，而不只运行一个无设备的单元测试。

## 后续验收证据

- 同总线上两台实际从设备，不同周期组与手动指令并行提交时，线路事务保持串行。
- 验证回显、首字节丢失、方向切换、设备超时、拔插和重复站号的诊断信息。
- 写命令已发出但无响应时显示结果未知，不自动重发可能有副作用的操作。
- 在实际波特率与响应时延下测量总线利用率、等待队列和超期，不能只展示配置周期。
