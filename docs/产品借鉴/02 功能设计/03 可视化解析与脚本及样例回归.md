# 可视化解析与脚本及样例回归的实现借鉴

核查日期：2026-10-24。本文是基于 GitHub 与官方资料的借鉴研究；“建议”不是已确认的详细设计，也不是已实现或实测结果。用户已选择 .NET 方向，具体版本与依赖尚未锁定。

## 结论

建议将可视化配置和脚本都转换为同一种受限的“输入报文到结构化结果”契约。先分帧，再解析；发送端先参数校验，再生成字节。脚本不是任意操作主机或绕过连接调度的后门。

## 弦桥建议落地

可视化先覆盖分隔符、固定宽度、字节偏移、类型/字节序、缩放和状态映射；复杂分支调用脚本。可视化规则与脚本统一输出值、单位、质量和诊断，不直接修改全局标签字典。所有字段验证成功后再提交同批更新。

发送脚本接收已验证参数，返回有限长度字节串；接收脚本接收完整帧与上下文快照，返回有限数量字段。脚本不能直接打开串口、建立网络连接、读写文件或调用控制；需要发设备命令时只能通过受控标签调度入口。

每个模板保存输入样例、预期结果、错误样例、规则版本和脚本摘要。预览与运行使用同一个解析引擎，避免网页预览正确而后台失败；修改后展示差异，不能自动“接受全部新快照”。

## 隔离与版本风险

Jint 官方明确它是进程内解释器，而非操作系统安全边界；限制不能抢占任意宿主回调。面向不可信导入脚本时，建议低权限独立进程加外部截止时间和资源边界，具体跨平台实现待设计。Roslyn 的引用白名单同样不能独立保证隔离。不要默认允许全部 CLR、反射或动态程序集访问。

可缓存编译/准备结果，但不要跨设备共享可变脚本状态；禁止无限输出、超长正则和无限循环。是否选 JavaScript 或 C# 尚待确认，不因后端是 .NET 自动选 C#。

## 后续验证证据

半帧不进入解析；粘包能分离；解析异常不写假 0；循环脚本被终止且其他连接继续；脚本无法绕过调度；同一批样例在 x64/ARM64 结果一致；脚本超时后资源确实释放。具体数据类型、大小和时间上限应写入验收指标。
