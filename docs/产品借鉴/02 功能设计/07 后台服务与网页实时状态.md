# 后台服务与网页实时状态的实现借鉴

核查日期：2026-10-24。本文是基于 GitHub 与官方资料的借鉴研究；“建议”不是已确认的详细设计，也不是已实现或实测结果。用户已选择 .NET 方向，具体版本与依赖尚未锁定。

## 结论

.NET Generic Host/BackgroundService 适合持有通讯与调度生命周期，ASP.NET Core 适合网页操作与推送。建议前端只订阅运行状态、提交调用意图，不持有串口周期任务。SignalR 是候选，不是已经选定的强制依赖。

## 已核查项目

- [dotnet/runtime](https://github.com/dotnet/runtime)：MIT，2026-10-24 最近推送；[Worker Services 官方文档](https://learn.microsoft.com/en-us/dotnet/core/extensions/workers) 明确支持跨平台后台服务与 Generic Host。
- [dotnet/aspnetcore](https://github.com/dotnet/aspnetcore)：MIT，main，2026-10-24 最近推送；[SignalR 源码目录](https://github.com/dotnet/aspnetcore/tree/main/src/SignalR) 可研究服务端与客户端生命周期。
- [SignalR 客户端重连](https://learn.microsoft.com/en-us/aspnet/core/signalr/javascript-client) 是显式配置的能力，默认并不自动重连；[stateful reconnect](https://learn.microsoft.com/en-us/aspnet/core/signalr/configuration?view=aspnetcore-8.0#configure-stateful-reconnect) 会缓冲、确认并重放消息，不能因此宣称工业写操作天然只执行一次。

## 弦桥建议落地

后台维护设备状态和调用状态，前端订阅快照及增量事件。每个事件带运行会话 Id、序号和时间；重连先核对会话，再取快照，日志缺口明确标示。页面暂时断开不影响后台已启动任务，但后台进程退出仍会中断任务。

状态流可合并高频标签更新，控制结果流不能随意丢弃。日志采用有界缓冲和分页；页面刷新频率独立于设备500ms读取周期，防止浏览器变慢反压串口。

为写入/动作建立客户端请求 Id 与后台调用记录：重复提交返回原调用状态，不重复发送。请求已送达但响应丢失时查询原调用，不能浏览器重连便自动重试。是否采用持久调用记录与保存期限需要用户确认；没有持久记录就不能承诺后台重启后仍具备去重保障。

## 范围与缺口

网页断线提示、重连同步和不重放控制是架构文档中的待确认建议，本文件说明如何研究实现，不把建议升级为新承诺。首次优先考虑同进程 Host+Web 的可维护边界；是否拆服务、多用户、远程访问、认证与TLS均需明确后设计。不要为通信测试工具默认引入云平台或集群。

## 后续验证证据

关闭全部网页后已运行定时任务继续；打开新网页可见当前状态；断线显示陈旧而非假实时；同一控制请求重复到达只发送一次；后台重启后的未知调用明确展示；日志洪峰不使浏览器或后台无限占内存；在各目标平台验证实际串口权限。
