# 统一标签与动作调用的实现借鉴

核查日期：2026-10-24。本文是基于 GitHub 与官方资料的借鉴研究；“建议”不是已确认的详细设计，也不是已实现或实测结果。用户已选择 .NET 方向，具体版本与依赖尚未锁定。

## 结论

优先借鉴 ThingsGateway 的通道、设备、变量分层，但弦桥应建立自己的“标签定义＋调用能力＋运行结果”边界，不把网关变量实体直接作为全部业务模型。用户需要的是测试和控制工具，不是复制一个采集转发平台。

## 已核查项目

- [ThingsGateway](https://github.com/ThingsGateway/ThingsGateway)：C#/.NET；仓库默认分支 v12，API 显示最近推送 2026-09-14，未归档。根 LICENSE 标 Apache-2.0；README 另列 PRO 插件和专业版，不能把它们一概视为免费开源能力。
- [Variable.cs](https://github.com/ThingsGateway/ThingsGateway/blob/v12/src/ThingsGateway.Gateway.Application/Entity/Variable.cs) 中可见单位、地址、数据类型、读写权限及读写表达式等配置；[Device.cs](https://github.com/ThingsGateway/ThingsGateway/blob/v12/src/ThingsGateway.Gateway.Application/Entity/Device.cs) 通过 ChannelId 关联通道，包含设备参数。它证明分层与元数据有参考价值，不证明它已经具备弦桥全部标签调用语义。
- [FUXA](https://github.com/frangoteam/FUXA)：TypeScript/Node.js，MIT，2026-10-22 最近推送、未归档。适合对照设备和标签的用户界面组织；不是可直接引用的 .NET 核心库。

## 弦桥建议落地

1. 标签定义保存稳定 TagId、设备实例 Id、显示名称、别名、单位、值类型和能力集合；改名不改绑定。
2. 调用能力明确分成读取、写值、动作；读取当前缓存值是查询运行状态，不等于触发通讯。
3. 协议绑定作为独立配置：串口查询模板、Modbus 地址、OPC NodeId/ItemId 或组合流程，不让前端直接拼协议报文。
4. 一次调用产生 OperationId，结果包含阶段、质量、值、时间和错误；数据更新可以同时影响多个标签。
5. “去皮”是动作能力，不伪装为给重量写 0；界面展示调用入口，但不以按钮数量定义功能。

以上是弦桥建议的数据边界，不是上游项目的原有类名或 API。具体公开 API 是否提供仍待确认。

## 不宜照搬与风险

- ThingsGateway 的变量采集、表达式与北向转发面向网关；直接复制会把测试、动作和诊断混进网关运行时。
- 未发现可直接满足全部统一标签、事务关联和未知控制结果语义的现成模型，弦桥仍需自行实现这些领域规则。
- 库支持 Windows/Linux 不代表串口驱动、OPC DA 或 Windows ARM64 均可用。

## 后续验证证据

改别名后地址不变；查看缓存时发送字节数不增加；只读标签拒绝写入；一条称重响应原子更新重量、单位、稳定性；解析失败保留旧值原时间并标无效；动作不能被普通监视读取意外触发。
