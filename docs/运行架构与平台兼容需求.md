# 弦桥 ChordBridge 运行架构与平台兼容需求

更新日期：2026-10-24  
状态：架构级需求记录；尚未实现、未进行跨平台或设备验收。

本文单独记录第二个想法：程序在后台运行，通过网页操作，并面向不同操作系统与处理器架构。业务能力继续以 [01 想法清单](01%20想法清单.md) 为依据；该文件原先标为待定的“应用形态、支持平台、关闭界面后运行方式”，以本文的新讨论为准，其余内容不变。

本文区分用户已确认的方向、为实现该方向作出的设计解释，以及仍需讨论的建议。不在此选择技术栈，也不把目标兼容范围写成已经通过验证的能力。

## 1 已确认的需求

### 1.1 跨平台与多架构

程序需要面向 Windows、Linux，以及 x64、ARM64 等 64 位运行环境。32 位操作系统不在支持范围内；此前提到的 x86 若指 32 位系统，已由本次决定排除。

操作系统与处理器架构是两层不同维度。后续必须按实际组合验证，不能只写一句“支持跨平台”就认为所有组合和协议均可用。

### 1.2 后台运行与网页操作

程序可以在后台运行，用户打开浏览器网页进行配置、测试、标签调用、定时任务操作与状态查看。网页是操作入口，不要求用户始终保持一个桌面窗口在前台。

这是一种后台程序与网页界面分工的应用形态，不等于要建设公有云平台，也不等于必须使用容器部署。

### 1.3 网页数据实时更新

用户所说的“实时更新”明确指网页上的数据与状态刷新，不是程序在线升级。

展示范围包括标签值、连接状态、执行结果和通讯日志。网页需要反映后台实际结果，而不是仅在用户手动刷新整页后才能看到变化。

“实时”是交互目标，不代表硬实时保证。具体刷新延迟、数据量、日志刷新节流及验收指标后续确定；设备读取周期和网页展示刷新周期不能混为一谈。

## 2 运行边界的设计解释

以下是对“后台运行、网页操作”的职责划分，具体运行与恢复细节仍需在方案阶段落实：

- 后台负责设备连接、协议收发、脚本与解析、标签调用、定时调度及执行状态。
- 网页负责配置、发起操作和展示结果，不承担必须持续运行的设备通讯循环。
- 按这一分工，关闭或刷新网页不应停止后台已经启动的连接和定时任务；重新打开时应能查看当前运行情况。这是后台独立运行的设计解释，不表示后台进程退出、主机关机或重启后任务也能继续。
- 设备通过串口或 USB 串口连接时，默认由运行通讯后台的主机持有端口。浏览器所在电脑与后台主机若不同，不能默认浏览器能直接使用其本机串口；其他接入方式需要另行设计。
- 标签、模板和调用规则应尽量跨平台复用。端口名称、设备驱动、路径等实例差异不能直接照搬；可复用不代表无需适配与测试。

后台如何安装、启动、停止，以及是否作为系统服务、是否开机启动或自动恢复，尚未选定。

## 4 协议兼容性边界

原有 RS232、RS422、RS485、Socket、Modbus RTU、Modbus TCP、OPC UA、OPC DA 的需求保留，不因采用网页界面或跨平台目标而删除。

串口和 USB 转串口适配器需要相应系统与架构的驱动及访问权限。网络协议也仍需检查所选依赖、连接行为和实际设备兼容性，不能根据协议名称直接宣称全部平台可用。

### 4.1 OPC DA 的平台限制

OPC Foundation 说明，OPC Classic 基于 Microsoft Windows 的 COM/DCOM 技术，OPC DA 属于该体系。因此，不能承诺将 Windows 的 OPC DA 连接实现直接原样运行在 Linux 上。[官方说明](https://opcfoundation.org/about/opc-technologies/opc-classic/)（核查日期：2026-10-24）

需要后续讨论的候选方式是：由 Windows 端连接 OPC DA，再向其他平台的后台提供桥接能力。是否采用桥接、桥接协议、部署位置与安全边界均未确定，本文不把它写成已选方案。

Windows ARM64 下的 OPC DA 组件、供应商驱动、进程架构及互操作能力也需单独评估，不能从“Windows”或“支持 ARM64”推导出 OPC DA 已兼容。若特定组合无法原生接入，应明确限制和替代路径，而不是隐藏缺失能力。

## 5 待确认的交互与可靠性建议

以下是助手提出、尚待用户确认的补充，不与已确认需求混写：

- 网页与后台断线时明确提示，避免旧值看起来仍在实时更新。
- 网页重连后同步后台当前状态，并标明需要补齐或无法恢复的日志范围。
- 不因网页刷新、重连或重复提交而自动重放写入与控制指令；不确定结果应可追踪和核对。
- 页面展示应区分设备采样时间、后台接收时间与页面更新状态，方便判断数据是否新鲜。
- 后台与网页的通信方式、更新节奏和拥塞时的处理，依据数据量和操作体验选择，不预先绑定框架或技术。

这些建议不改变第一份清单已经确认的标签调用、同周期定时组、完整事务、中断及失败处理语义。

## 6 尚待讨论的架构选择

- 支持的 Windows 版本、Linux 发行版及各架构的正式交付优先级。
- 后台安装包、运行时依赖、系统服务、开机启动和进程异常恢复方式。
- 网页仅限本机访问，还是允许局域网访问；若开放访问，相应的身份验证、授权和传输保护要求。
- 是否允许多个浏览器或用户同时操作，以及配置变更和控制冲突如何处理。
- 任务、模板、标签配置、运行结果和日志的持久化范围；后台重启后是否以及如何恢复任务。
- OPC DA 原生连接与桥接的具体边界，以及旧组件和 ARM64 驱动兼容策略。
- 实时刷新延迟、可承载标签数量、并发连接数量与日志量的可验证指标。
- 技术栈、前后端通信机制、脚本运行环境和打包发布方式。

软件在线升级不属于本次“实时更新”要求，不默认加入交付范围。
