# 设备模板与实例及版本差异的实现借鉴

核查日期：2026-10-24。本文是基于 GitHub 与官方资料的借鉴研究；“建议”不是已确认的详细设计，也不是已实现或实测结果。用户已选择 .NET 方向，具体版本与依赖尚未锁定。

## 结论

借鉴配置可移植、模式验证和版本化思想，模板不应等于整台设备配置的复制品。建议采用“不可变模板版本＋实例连接参数＋显式覆盖＋升级差异预览”。尚未找到无需改造即可完整满足弦桥规则的 .NET 成品。

## 已核查项目

- [ThingsGateway Device 实体](https://github.com/ThingsGateway/ThingsGateway/blob/v12/src/ThingsGateway.Gateway.Application/Entity/Device.cs)：设备和通道关联、实例属性字典可作分层参考。v12，2026-09-14 最近推送；Apache-2.0 根许可，商业插件另审。
- [json-everything](https://github.com/json-everything/json-everything)：.NET 的 JSON Schema、JSON Pointer、JSON Patch 等组件；默认 master，2026-10-17 最近推送，未归档。源码 [LICENSE](https://github.com/json-everything/json-everything/blob/master/LICENSE) 是 MIT，但 [OSMFEULA.txt](https://github.com/json-everything/json-everything/blob/master/OSMFEULA.txt) 对发布二进制列有维护费约定，商用不能只看 MIT 徽章。作为候选而非已选依赖。
- [Elsa Workflows](https://github.com/elsa-workflows/elsa-core)：MIT，2026-10-24 最近推送，支持工作流版本化；可借鉴“定义版本”和“运行实例”分开，不代表需要把模板变为完整 Elsa 工作流。

## 弦桥建议落地

模板包含协议类型、命令与解析规则、脚本、标签定义、默认参数、样例测试集和兼容说明；实例只引用模板版本，并保存端口/IP、站号、凭据引用与批准的覆盖。凭据内容不进入可分享模板。

升级时展示旧模板、新模板和实例覆盖的三方差异：地址变化、标签删除、类型/单位变化、写入能力增加属于需重点核对的变更。先离线重跑样例，再由用户选择实例升级；正在执行的事务绑定旧配置快照，避免半轮切换。

建议使用版本号＋内容摘要记录实际运行配置。导入仅解析与验证，不自动连接设备或执行脚本。将未知字段、重复标识、失效引用和超出限制的配置明确报错。

## 缺口与取舍

JSON Schema 能检查结构，不能单独验证“模板升级不会改变泵的行为”；JSON Patch 是变更表达方式，不是用户友好的差异界面或安全审批。轻量版本可先用 System.Text.Json 和明确的业务校验，待复杂度证明需要后再引入模式库。两种方案都需保留迁移测试。

## 后续验证证据

同模板两设备的端口修改互不影响；模板新版不静默替换已绑定版本；实例覆盖在升级时提示冲突；模板导入不打开串口；删除仍被流程引用的标签被阻止；失败升级仍保留可恢复的旧版本。配置保存方式、跨用户编辑冲突与持久化范围仍需定案。
