# 弦桥 ChordBridge 技术方案

版本：设计建议稿 v0.2（已纳入四组决策）  
日期：2026-10-25（组件资料核查日期仍为 2026-10-24）  
状态：.NET 实现方向、原有业务需求及第 13 节四组决策已经确认；具体组件、未明确确认的工程策略仍为建议，兼容性仍待验证。尚未编码、安装依赖或进行设备与平台验收。

## 1 方案结论和边界

建议采用 **.NET 10 LTS 后台宿主 + Vue 3 网页界面 + 统一标签调用核心 + 按连接执行器 + SQLite 配置存储**。复用协议类库，不整体改造某个工业云平台；把网页、设备通信、脚本执行和平台兼容边界分开。

最终交付范围必须覆盖用户列出的 **RS232、RS422、RS485、Socket、Modbus RTU、Modbus TCP、OPC UA、OPC DA**，以及已经确认的全部功能。分阶段仅安排验证和实现顺序，不能把后续协议或难点删除为“暂不支持”的最终结论。对 OPC DA 等平台受限能力，必须保留接入路径、验证门槛及明确限制。

业务依据：[01 想法清单](01%20想法清单.md)。运行形态依据：[运行架构与平台兼容需求](运行架构与平台兼容需求.md)。组件调查依据：[产品借鉴索引](产品借鉴/README.md)。对象关系、执行状态和模块职责由 [04 架构方案](04%20架构方案.md) 具体说明。

本文不新增公有云、多租户、组态画布、长期时序数据库、告警平台或自动运维，也不把第三方项目的全部功能搬进弦桥。

## 2 技术选型总表

| 技术位置 | 优先建议 | 备选及切换条件 | 主要取舍与验证门槛 |
| --- | --- | --- | --- |
| 后端运行时 | .NET 10 LTS、C#，锁定受支持补丁 | 旧组件隔离在兼容进程，不让整个主程序退回旧 .NET Framework | 验证所有依赖与四个目标运行组合；不是只验证能启动 |
| Web 与后台宿主 | ASP.NET Core、Generic Host、BackgroundService | 不优先引入完整微服务框架 | 设备循环不依赖浏览器或一次 HTTP 请求的生命周期 |
| 网页界面 | Vue 3 + TypeScript + Vite + Element Plus | Blazor；若团队坚持全 C# 或前端维护成本无法接受，再做对照原型 | Vue 便于高密度标签表、拖放和编辑器集成；需要维护前后端契约 |
| 编辑器与图表 | Monaco Editor 按需加载；Apache ECharts 绘制短趋势 | 更轻的文本编辑器/图表仅在体积与性能证据支持时替换 | 不把编辑器加载成本和全量数据刷新压到首页 |
| 网页实时状态 | SignalR + 初始快照 + 增量状态 | 原生 WebSocket；只有测出 SignalR 明显不适合才替换 | 不用实时推送连接承担设备事务，不因重连重放控制 |
| 定时与连接队列 | 单调时间的内存调度 + 有界 Channels + 每连接执行器 | Quartz 只在未来确有日历调度需要时评估 | 500 毫秒不是硬实时承诺；Hangfire recurring 不作亚秒通信核心 |
| 数据持久化 | SQLite + EF Core 10，配置与必要执行证据 | Microsoft.Data.Sqlite 直接访问用于经测量确有需要的简单路径 | SQLite 写入与迁移有边界；不把每次标签变化无上限写数据库 |
| 模板与解析 | 自有版本化 JSON 结构 + 可视化规则模型 | JSON Schema 辅助校验可后选，但不绑定存在许可疑问的二进制包 | 结构校验和业务校验分开，先看升级差异再应用 |
| 脚本 | Jint 已发布 4.16.x 维护线，独立脚本工作进程与窄接口 | Roslyn C# 脚本只作为确有需要时的替代路径 | 不跟随未发布 main；独立进程加语言限制也不自动等于安全沙箱 |
| 应用日志 | Microsoft.Extensions.Logging 接口 + Serilog 滚动文件 | 默认日志提供器可用于最初验证 | 日志有容量上限、脱敏和调用关联；不把日志失败伪装正常 |
| 主机监视 | 自有平台采集接口，对照 SystemMetrics 与 .NET 系统 API | 各操作系统独立采集器 | 磁盘空间与读写速率是不同指标，全部逐平台核验 |
| 部署 | 按运行组合生成自包含发行包，随包携带网页资源 | 环境受控时提供框架依赖包；容器作为后续选项 | 用户运行不需 Node.js、不依赖 CDN；服务安装与权限另行确认 |

以上是建议组合，不是已经完成集成的依赖清单。确切第三方包版本在原型通过后锁定，并保存锁文件、许可证及依赖清单；不使用浮动 `latest`。

## 3 运行时和发布策略

### 3.1 为什么推荐 .NET 10

截至核查日，微软官方支持策略将 .NET 10 列为 LTS，支持至 2028-11-14；.NET 8 与 .NET 9 的支持将于 2026-11-10 结束。因此，新项目不宜为了“熟悉”而默认从即将结束支持的版本起步。本方案推荐 .NET 10 当前受支持的稳定补丁，不使用 .NET 11 预发布作为生产基线。[官方支持策略](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core)

SDK 版本与运行时补丁版本分别锁定；不能把运行时补丁号当 SDK 版本号。框架升级需重跑协议、脚本、持久化和打包回归，更新依赖不等于完成软件在线升级功能。

### 3.2 发布形态

建议一个后台宿主承载 Web、配置和调度；脚本执行与 OPC DA 等需要独立边界的部分使用辅助进程。不是为每个标签或定时组启动一个进程。

前端在构建时产出静态资源，随发行包部署，由后台同源提供。用户运行时不需要 Node.js，也不需要外网 CDN 才能打开页面、编辑模板或看趋势。图标、字体、编辑器 worker 和图表资源均需离线打包验证。

第一阶段不默认采用单文件、裁剪或 Native AOT，避免反射、脚本、插件或原生依赖在尚未验证时被裁掉。自包含包体积较大但现场部署简单；之后再用测量结果决定优化。

后台可以以前台命令方式启动用于调试；正式运行建议支持 Windows Service 与 Linux systemd。是否开机启动、使用什么服务账户、安装目录与权限由部署方案确定，不能在当前设计阶段自动改系统设置。

## 4 网页技术与交互建议

### 4.1 Vue 方案优先的理由

弦桥主要是连接树、可编辑标签表、报文预览、规则编辑、拖入定时组和执行记录。建议 Vue 3 + TypeScript 配合 Element Plus，避免自研通用表格、表单和对话框。Vue 与 Element Plus 的许可证为 MIT。[Vue 官方说明](https://vuejs.org/about/faq)；[Element Plus 仓库](https://github.com/element-plus/element-plus)

这不是把界面确定为某个固定成品主题。页面以标签及调用为核心，执行入口可以是行操作、命令输入或详情面板，不以给每个设备制作一组按钮为产品模型。具体布局留给 UI 方案阶段。

Blazor 是有效备选：可以复用 C# 经验，但仍需处理 JavaScript 编辑器和图表集成；服务器交互模式还需要考虑 UI 连接生命周期。无论选哪种模式，设备通信都不能挂在页面或组件生命周期里。[Blazor 官方托管模式](https://learn.microsoft.com/en-us/aspnet/core/blazor/hosting-models?view=aspnetcore-10.0)

### 4.2 编辑器、趋势与大数据表

- Monaco 只在脚本编辑区按需加载，并验证 worker 的离线路径与内容安全策略。它是编辑器，不是脚本执行环境。[Monaco](https://github.com/microsoft/monaco-editor)
- ECharts 用于主机和标签短时趋势，按窗口合批刷新，不为每个值变化重建整个图表。[ECharts](https://github.com/apache/echarts)
- 标签表采用分页或虚拟化，后端推送按订阅范围过滤；不能把所有原始报文广播给所有页面。
- 原始报文区域支持暂停显示与查看历史片段；暂停显示不等于暂停后台任务，界面必须分清。
- 初步以当前受支持的桌面 Edge、Chrome 作为验证对象；具体版本和其他浏览器支持清单待验证，不承诺所有浏览器与手机完整编辑体验。

### 4.3 命令与状态分开

建议网页的配置和调用通过有类型的受控 HTTP 接口进入后台，SignalR 用于状态更新。这里是程序自身的网页通信接口，不等于已经承诺对第三方发布公共 API。

网页先获取当前快照，再接收带序号的变化；重连后重新同步。写入与动作携带调用标识，后台先检查重复与执行状态，再决定是否接受。网络断开不证明命令未执行，页面不得自动重放“最后一次点击”。这些可靠性机制落实不自动重放控制的安全边界；具体实现仍需验证。

## 5 八类接口与协议的完整技术路径

| 范围 | 优先技术路径 | 备选与限制 | 必须提供的证据 |
| --- | --- | --- | --- |
| RS232 | System.IO.Ports 包装为统一串口传输，模板处理请求响应 | RJCP SerialPortStream 用于实际缓冲、取消或平台行为不满足时的对照；不能只凭接口相似替换 | 波特率/校验位/终止符、半帧、断线、超时和实际适配器测试 |
| RS422 | 复用串口传输与模板，记录实际适配器/接线模式 | 电气层差异由硬件与驱动决定，不另造一个“RS422协议库” | 实际 RS422 设备、端口参数和目标平台驱动证据 |
| RS485 | 串口传输之上建立物理总线独占执行、方向控制策略 | 优先硬件自动方向；手动 RTS 等只在适配器支持并实测后使用 | 多站地址、半双工切换、总线争用、超期、迟到响应 |
| Socket | 优先评估 TouchSocket 开源传输/分帧适配；业务关联逻辑自有 | System.Net.Sockets/Pipelines 为低依赖备选；SuperSocket 为服务端接入对照；已确认 TCP 主动连接与被动监听接入、UDP 发送与接收监听全部模式 | TCP 半包粘包；UDP 来源、重复、乱序、丢包；缓冲上限与重连 |
| Modbus RTU | 优先 NModbus 稳定线，串口适配接入共同连接执行器 | FluentModbus 对照；实际功能码、串口适配与依赖图必须核对 | CRC、地址偏移、字节序、异常码、总线独占、写后读完整流程 |
| Modbus TCP | 与 RTU 尽量共用 NModbus 标签映射和测试资料 | FluentModbus 对照；不因 TCP 可并发就无条件并发写设备 | MBAP/事务关联、设备并发限制、批量边界和失联未知结果 |
| OPC UA | OPC Foundation 官方 .NET 客户端栈的已发布稳定包 | Workstation.UaClient 为轻量对照；官方 2.x 与旧维护线 API/许可按实际版本核对 | 浏览、Read/Write、订阅、证书、质量/时间、断线恢复和服务端修订速率 |
| OPC DA | 单独 Windows DA 兼容进程，经统一接口接入后台 | TitaniumAS 用于旧组件可行性评估；商业 QuickOPC 作成本对照，未授权采购；最终 SDK 与桥接方式须验证 | 现场 DA 服务器、COM/DCOM、组件位数、读写订阅、阻塞隔离及平台路径 |

串口三类需求分别保留，但共享传输抽象，避免维护三套重复代码。Socket 已确认覆盖 TCP 主动连接（客户端）、被动监听并接受连接（服务端），以及 UDP 主动发送、绑定本地端口接收／监听。UDP 是无连接数据报，不套用 TCP 的连接建立、accept 或重连语义；需校验来源、报文边界和关联，分别处理丢失、重复与乱序。所有模式均需验证，不能拿“支持 TCP”自动宣称其余模式完成。

当前研究可见 NModbus 3.0.83 稳定包、FluentModbus 5.3.2，以及官方 UA 2.x 发布线，但它们均不是本方案已安装或验收的版本。具体版本及依赖图由实施前检查锁定，预发布和滚动分支不作为默认依赖。

协议资料入口：[串口与 Socket](产品借鉴/01%20通讯协议/01%20RS232%20串口测试与指令标签.md)、[RTU](产品借鉴/01%20通讯协议/05%20Modbus%20RTU%20寄存器与事务.md)、[TCP](产品借鉴/01%20通讯协议/06%20Modbus%20TCP%20连接与批量读写.md)、[UA](产品借鉴/01%20通讯协议/07%20OPC%20UA%20浏览订阅与标签映射.md)、[DA](产品借鉴/01%20通讯协议/08%20OPC%20DA%20Windows%20兼容与桥接.md)。

### 5.1 四种目标组合的交付路径

| 运行组合 | 核心后台与网页 | 串口、Socket、Modbus、UA | OPC DA 路径 |
| --- | --- | --- | --- |
| Windows x64 | 原生 .NET 发行包目标 | 逐依赖、驱动和设备验证 | 优先同机独立 Windows 兼容进程；远程 DA 另验 DCOM |
| Linux x64 | 原生 .NET 发行包目标 | 逐依赖、驱动和设备验证 | 通过已验证的 Windows DA 代理接入，不声称 Linux 原生 COM/DCOM |
| Linux ARM64 | 原生 .NET 发行包目标 | 尤其验证 USB 串口与原生依赖 | 同上，保留系统级 DA 能力与代理部署要求 |
| Windows ARM64 | 原生 .NET 发行包目标 | 逐依赖和 ARM64 驱动验证 | 先核查原生组件；如不具备可用组合，使用已验证 Windows x64 代理路径 |

以上均为目标路径，当前没有通过实测的兼容组合。OPC DA 不能被删掉，但也不能为了“全平台”而虚构 Linux 原生支持。用户已确认使用 Windows、Linux 设备，并允许采用 Windows 代理接入 OPC DA。上述 x64／ARM64 仍是既有交付目标，不是本次回答确认的实际硬件清单；具体系统版本、处理器、驱动、DA 服务器和组件组合需后续收集验证。代理同机或跨机拓扑、通信保护及服务账户按现场条件确定，设计选择不等于已执行部署或获准修改系统权限。

只排除 32 位操作系统。旧 DA 服务器若需要在 64 位 Windows 上使用 32 位辅助组件，属于独立待评估依赖，不自动获得采用许可。

## 6 标签模板和解析技术

标签与动作都通过统一调用契约进入后台，不让某个协议 SDK 的类型成为网页和存储模型。建议将标识、名称别名、类型单位、来源、能力和调用定义分开；改别名不改绑定地址。

模板用版本化 JSON 保存通用规则，实例保存连接参数及覆盖项。可视化编辑与脚本共用同一套解析/生成契约，网页预览调用后台的同一规则引擎，不另写一套 JavaScript 解析实现。

解析顺序建议固定为：分帧、完整性校验、字段解析、类型与范围校验、生成带质量和时间的结果批次。发送端是参数校验、规则或脚本生成、最终长度与权限检查，再交给连接执行器发送。

需要明确的工程细节：
- 原始字节与工程值均可追踪，单位转换不丢原值。
- 64 位整数及高精度小数不能直接丢给 JavaScript Number；跨网页契约采用类型标识与无损文本表示等方式。
- 多字段响应只发一次查询，各标签共享来源批次，字段缺失与整帧失败的更新策略要可验证。
- 保存成功与错误样例，模板版本变化后重跑，不自动把新输出覆盖为“正确答案”。

MT-SICS、OHAUS 等称重模板按设备型号和手册版本维护，不能把某一台秤的指令假设泛化到所有称重设备。[称重案例借鉴](产品借鉴/02%20功能设计/10%20MT-SICS与称重设备标签化案例.md)

## 7 脚本方案与安全边界

建议优先 JavaScript + Jint 已发布的 4.16.x 维护线，用于发送参数处理、校验码辅助计算、响应解析与数值转换。核查时上游 main 为未发布 5 开发线，不能直接以 main 文档 API 编写面向稳定包的实现。[Jint 仓库](https://github.com/sebastienros/jint)；[发布记录](https://github.com/sebastienros/jint/releases)

推荐脚本只接受有限输入，输出有限长度字节或结构化字段；不开放 CLR、反射、文件、网络、进程或原始串口。需要执行标签操作时，由外部流程调度；若后续用脚本编排组合流程，也只能通过受控标签调用入口进入同一调度，不能直接访问串口。解析脚本与流程编排职责分开，不因共享脚本语言而获得设备控制权限。

独立脚本工作进程用于故障隔离和外部截止时间，宿主负责启动、限制并回收它。限制执行步数、输入输出尺寸、内存和运行时间；但 **Jint 限制与进程拆分都不能单独证明对恶意脚本安全**。低权限身份、文件与网络能力隔离的 Windows/Linux 实现需要独立验证。

用户已确认会导入外部模板／脚本，因此必须把外部内容视为不可信输入。导入只校验与保存，不执行脚本、不连设备、不启用定时任务；展示来源、脚本、版本差异与影响范围，经用户明确批准启用后才可进入运行范围。隔离与资源限制验收通过是运行前提，离线脚本预览也适用这些边界；批准导入不等于批准执行或设备控制。

Roslyn C# 脚本为备选，不与 JavaScript 双语言同时起步。只有现有设备脚本大量依赖 C# 或工程团队明确需要时才评估；引用白名单不是可靠的任意 C# 沙箱。[Roslyn 脚本示例](https://github.com/dotnet/roslyn/blob/main/docs/wiki/Scripting-API-Samples.md)

## 8 定时和事务技术

建议调度层使用单调时间与有界队列，连接执行器持有串口或会话。定时组每轮产生“调用意图”，手动请求也进入同一执行器。所有写入、解析脚本和组合流程都不能绕过这层。同一个物理串口上的多个设备实例共享一个执行器，不能按设备各建队列后并发争用同一端口。

- 设置 500 毫秒自动创建或复用 500 毫秒组，拖入采用该周期；2 秒独立组。不存在组内各标签继续不同周期的另一套逻辑。
- 一条查询后收响应是一个读取事务；真正写参数再读回是一个组合事务。
- 超期不叠加同一操作、不无限补跑；显示期望时间、实际开始、结束和排队耗时。
- 只合并等价且无副作用的读取；定时写入和动作不能通过去重擅自改变次数。
- 默认手动排队；用户选择中断时进入协议恢复流程，不能把取消令牌当作已经撤销物理命令。
- 支持按连接暂停、恢复定时任务，暂停期间其他连接继续；连续手动调试时避免后台周期写入覆盖新设置。暂停是停止新的定时触发，不等于撤回已经发出的命令。
- 没有事务号的串口不能保证任意时刻立即抢占并准确匹配，恢复期间应拒绝或等待新发送，而非用迟到响应污染结果。

.NET PeriodicTimer 等是构件，不是完整设备调度器。Quartz 可表达更复杂计划，但没有必要为亚秒周期引入持久化作业平台；Hangfire recurring 的分钟检查机制不适合直接承担本需求。[调度借鉴](产品借鉴/02%20功能设计/04%20同周期定时组与合并调度.md)

## 9 配置存储与执行证据

建议 SQLite 保存连接配置、模板版本、实例覆盖、标签定义、定时组及调用记录的必要元数据，EF Core 10 管理模型和迁移。高频最新值与主机短趋势用有界内存缓存，不默认建设长期历史库。

记录至少能关联调用标识、配置版本、发起来源、目标、开始结束时间、步骤和结果。原始报文日志采用可配置且有容量上限的滚动保存；保留期和脱敏规则待确定，不无上限占满现场磁盘。

SQLite 适合单机部署，但写入需要有界排队；设备通信的关键接收循环不能等待长数据库事务。迁移、备份、异常中断恢复和旧版本读取都要测试，不能只调用 ORM 自动迁移便认为可安全升级。[官方 SQLite Provider](https://learn.microsoft.com/en-us/ef/core/providers/sqlite/)；[限制说明](https://learn.microsoft.com/en-us/ef/core/providers/sqlite/limitations)

配置并发建议使用显式版本号并进行乐观冲突检查；不能依赖 SQLite 提供其他数据库同样的自动行版本能力。凭据不随模板导出、不记入报文日志，采用操作系统凭据保护或受保护配置引用，具体机制按平台验证。

对具有副作用的调用，建议发送前落下必要执行意图；若无法记录，不静默继续控制。后台崩溃后既不能宣称成功，也不能自动重发未确认控制。重启暂停与不自动重放已确认，执行意图落盘的具体实现仍需验证。

## 10 主机资源监视与可观测性

主机状态必须指后台所在主机，包含整机 CPU、内存、各网卡速率、磁盘容量/剩余空间和读写速率、短趋势，以及弦桥自身进程 CPU/内存。

建议 Windows 与 Linux 分别实现采集器，统一输出单位、采样时间、范围和可用性。.NET 的 Process、NetworkInterface、DriveInfo 可覆盖部分数据；主机 CPU 和磁盘 I/O 还需操作系统计数来源，不能用进程 CPU 代替整机 CPU，或用磁盘剩余空间冒充吞吐。

采样初期、权限不足、设备消失或计数重置时显示不可用，不产生假零或异常负速率。CPU 口径、物理磁盘/卷映射、容器与宿主机范围要明确。每台后台只采样一份数据，不因多个网页连接增加采样循环。

建议主机采样从 1 秒、短趋势从 10 分钟有界窗口开始做原型测量；这只是候选初值，不是用户已指定指标，也不跟随 500 毫秒设备组改变。不得新增清磁盘、杀进程、自动调优、告警或长期存储。[主机监视借鉴](产品借鉴/02%20功能设计/08%20主机资源监视与短时趋势.md)

## 11 已确认的访问与恢复边界

用户已确认网页只在后台主机本机使用：Web UI、内部 HTTP API 与 SignalR 均限定本机回环地址（127.0.0.1／::1），不绑定通配地址，不开放局域网或公网管理入口。该限制只针对管理平面，不禁止后台访问网络设备，也不排除经独立受控通道连接 Windows DA 代理；Socket 设备侧监听需独立配置绑定地址、端口及允许来源，不能顺带暴露 Web 入口。即使本机使用，也不能把任意网页发来的请求视为设备控制授权；同源、来源检查与防跨站请求机制需验证。

用户已接受后台重启后恢复配置与证据、全部定时任务先保持暂停（包括读取）；写入、动作和组合控制不自动恢复，不补跑停机期间的控制，也不重放未知结果。恢复须显式操作；若将来需要安全只读任务自动恢复，应作为另行确认的变更，当前未启用。浏览器关闭不停止当前后台任务，与后台重启后如何恢复是两个不同问题。

本机使用不等于只允许一个浏览器标签页，也不代表已确认多人同时控制。保留同机多页面的配置版本冲突检查、调用身份和统一排队；多操作员控制权／角色模型仍是设计细节，不作为本次新增已确认需求。

以上记录已确认边界及其工程落实要求，不表示已经修改用户系统、开放网络或执行设备操作。
