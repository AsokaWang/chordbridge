# 配置与通讯日志可追溯的实现借鉴

核查日期：2026-10-24。本文是基于 GitHub 与官方资料的借鉴研究；“建议”不是已确认的详细设计，也不是已实现或实测结果。用户已选择 .NET 方向，具体版本与依赖尚未锁定。

## 结论

用结构化事件记录通讯事务，而非把所有字节和异常拼成长字符串。保留“使用哪版模板、哪次调用、哪个步骤、实际发送到哪一步”的关联，才能解释写入结果未知和解析规则变化。

## 已核查项目

- [Serilog](https://github.com/serilog/serilog)：Apache-2.0，dev，2026-10-23 最近推送，未归档；结构化事件机制适合按设备与调用检索。
- [Serilog file sink](https://github.com/serilog/serilog-sinks-file)：[LICENSE](https://github.com/serilog/serilog-sinks-file/blob/dev/LICENSE) 为 Apache-2.0；支持按时间或大小滚动，适合作为有限日志文件候选。保存时长和落盘范围仍待产品确认，不能默认保留无限历史。
- [.NET Channels](https://github.com/dotnet/runtime/tree/main/src/libraries/System.Threading.Channels)：MIT；可为日志显示建立有界异步流，但不能无声丢弃关键控制结果。

## 弦桥建议落地

事件字段建议包括：运行会话、连接、设备、标签、调用、步骤、模板版本、脚本摘要、方向、时间、字节长度、阶段、错误分类。原始字节保留HEX视图，文本只是按指定编码的显示，不应反过来作为唯一原始证据。

将设备业务日志、原始报文、系统诊断分开。读取失败、解析失败、校验失败、操作未知等有独立分类；发送成功与物理执行成功不能使用同一布尔值概括。

配置保存采用校验后原子替换或事务提交，记录配置版本；运行中事务使用已捕获版本。日志保存新旧版本标识，但凭据、口令、认证报文需脱敏，不为追踪把秘密写入文件或导出模板。

前端日志使用分页与过滤，不一次加载整份文件。缓存满、磁盘满、日志被截断必须有统计和提示；日志写入故障不能导致控制操作被重发。将“我没有日志”与“设备没有执行”分开。

## 不宜照搬

采用 Serilog 不等于建立不可篡改审计，也不能满足法规电子记录要求；这些不是本次范围。任意 sink 可能有不同许可证与外部服务依赖，不能直接沿用核心库许可结论。日志导出和数据保留需按后续明确的安全及容量要求实现。

## 后续验证证据

从一个标签错误能追到对应原始响应和模板版本；跨并发连接不串日志；中文及二进制字节原样可核对；配置编辑不会改变正在执行事务；日志满盘不会无限重试设备命令；导出不含凭据；程序异常后未知状态有证据而非被清成成功。
