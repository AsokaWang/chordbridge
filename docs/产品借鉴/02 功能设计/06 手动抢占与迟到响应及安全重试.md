# 手动抢占与迟到响应及安全重试的实现借鉴

核查日期：2026-10-24。本文是基于 GitHub 与官方资料的借鉴研究；“建议”不是已确认的详细设计，也不是已实现或实测结果。用户已选择 .NET 方向，具体版本与依赖尚未锁定。

## 结论

用每连接一个执行器统一处理定时和手动任务；“立即”应解释为请求中断并进入安全恢复过程，而不是取消 Task 后立刻让第二条指令抢占串口。没有事务标识的设备无法仅靠软件令牌识别所有迟到响应。

## 已核查构件

- [.NET Channels](https://github.com/dotnet/runtime/tree/main/src/libraries/System.Threading.Channels)：MIT，runtime 最近推送 2026-10-24；[官方文档](https://learn.microsoft.com/en-us/dotnet/core/extensions/channels) 提供有界队列、多生产者/消费者与满队列策略。可实现调度构件，不自动提供硬件事务取消。
- [Polly](https://github.com/App-vNext/Polly)：BSD-3-Clause，main，2026-10-24 最近推送；[重试策略](https://github.com/App-vNext/Polly/blob/main/docs/strategies/retry.md) 提供条件、次数与退避。README 公告将维护费限定于 2026-11-16 之后发布的下一个主版本及直接引用；现有版本不受该费用影响，间接依赖不适用该公告条件。达到公告收入门槛的商业使用需核查实际版本条款，源码许可仍为 BSD-3-Clause。不能写成 Polly 当前整体收费，也不能只写“完全免费无条件”。
- [Node-RED serial request](https://github.com/node-red/node-red-nodes/blob/master/io/serialport/README.md) 可作逐请求串行模型参照；它不证明任意中断后都能可靠匹配响应。

## 弦桥建议落地

默认手动任务排到当前完整事务之后；高优先级不等于可插入组合中间。用户选择中断时，执行器取消尚未发送的步骤，记录已发送步骤的未知结果，并切换连接世代。

连接世代只隔离软件内旧回调，不能标记线上无 Id 字节。驱动需提供协议特定恢复策略：等待可判定结束、丢弃并记录旧帧、必要时关闭重开连接，或要求人工恢复。禁止假设“清空缓冲区一次”能消除随后到来的旧响应。

定时暂停应阻止后续入队，并展示队列中任务如何处理；当前事务默认完成，显式中断另走恢复流程。恢复定时任务不追赶积压写入。

## 重试边界

为每种调用声明可重试条件；只有已证明安全的读取才可有限重试。写入和动作发生超时后，若字节可能已发送，标未知，先按协议允许方式读回核对；不能把 Polly 的通用异常重试直接包在所有串口读写外层。禁止控制请求的并行 hedging。重连与重发是两件事。

## 后续验证证据

超时旧响应在下一次请求后到达，不误更新新请求；取消发生在发送前/发送后得到不同结果；同连接并发请求被串行；队列满时明确拒绝或背压；一个驱动卡死不会无限占满线程；去皮超时没有自动二次发送；恢复操作不把未知改成成功。
