## 1 范围和设计原则

### 已确认的产品约束

- 用 .NET 编写后台，网页负责操作和实时展示，面向 64 位 Windows、Linux、x64、ARM64 目标；不支持 32 位操作系统。
- 完整覆盖 RS232、RS422、RS485、Socket、Modbus RTU、Modbus TCP、OPC UA、OPC DA。
- 先测试通讯，再沉淀指令、分帧、解析、脚本、标签与模板；已有模板可跨设备复用。
- 可视化和脚本同时支持发送与接收，以标签读取、写入和动作调用为统一使用入口，不以制作按钮为核心。
- 标签独立定义；设置周期自动创建或复用定时组，拖入组采用组的统一周期。
- 支持完整查询事务和真正的先写后读组合；同串口不能随意交错；手动既能排队也能请求中断。
- 失败、超时、旧值、迟到响应和结果未知必须明确，不伪造成功或零值。
- 展示后台主机及弦桥进程资源，仅监视，不加入系统控制或自动运维。

- 2026-10-25 补充确认：网页只在本机使用；使用 Windows、Linux 设备，允许 Windows 代理接入 OPC DA；后台重启后全部定时任务先暂停；会导入外部模板／脚本；Socket 覆盖 TCP 主动连接／被动监听接入与 UDP 发送／接收监听。实际系统版本和硬件架构未由本次回答确定。

### 推荐的架构取舍

采用**模块化单体后台，加必要的进程隔离**。单主机服务承载核心业务、调度与网页服务；只有存在明确兼容性或隔离理由的部分才拆成进程，例如 Windows OPC DA 适配器、不可信脚本工作进程。

不先引入微服务集群、消息中间件集群、完整工作流平台、云管理或 SCADA 组态。不是削减需求，而是让现有需求由足够简单、可测试的模块完成。

所有协议库放在适配器内部。标签、定时组和调用状态不依赖某个 SDK 的类型，这样后续更换通讯库不会推翻整个产品。

## 2 系统边界和运行结构

```text
本机浏览器操作界面（Web／API／SignalR 仅回环）
  配置与调用请求                  实时快照与增量状态
        │                              ▲
        ▼                              │
┌──────────────── .NET 后台宿主 ────────────────┐
│ Web 入口与访问控制       实时投影与浏览器会话      │
│          │                     ▲               │
│ 应用服务：连接、模板、标签、调试、定时组、执行记录  │
│          │                     │               │
│ 领域模型与调用规划 ──→ 运行结果及标签状态仓库      │
│          │                     ▲               │
│ 定时调度＋手动入口 → 连接资源执行器 → 协议适配器   │
│                         │            │         │
│ 配置持久化／有界执行证据  │   主机资源采样与短趋势 │
└─────────────────────────┼────────────┼─────────┘
                          │            │
           受限脚本工作进程             │
                                       ├─ 串口／Socket／Modbus／OPC UA
                                       └─ Windows OPC DA 适配进程 → DA 服务器
```

图中的脚本进程、DA 进程为建议部署边界；是否同机、跨机和通信方式需要按现场条件确定。浏览器不会直接持有串口，也不负责轮询；关闭网页不停止后台已运行任务。后台退出、主机关机或重启时任务无法继续，恢复策略必须另行控制，不能表述成“永不中断”。

后台与设备在同机或可达网络通信。已确认管理网页仅本机使用：Web UI、内部 API 与 SignalR 仅绑定 127.0.0.1／::1，不绑定通配地址或开放局域网／公网管理入口。此限制不禁止设备网络通信或跨机 Windows DA 桥接；两者属于独立设备通道，不能顺带暴露 Web 管理面。

## 3 模块职责与依赖规则

以下模块名用于说明职责，具体项目名称可在实施前微调。

| 模块 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| Domain | 标签、模板、调用、周期组、质量与执行结果等业务规则 | 不引用串口库、Web 框架、数据库或 UI |
| Application | 保存配置、预览、调用标签、启停组、取消运行、查询结果等用例 | 不直接打开设备连接，不混入网页布局 |
| Runtime | 连接资源管理、执行器、队列、周期调度、事务和组合运行 | 不自行改变已确认的标签和组语义 |
| Protocols | 各协议适配、能力声明、分帧、关联、读写、浏览或订阅 | 不持有整个产品数据库，不直接向页面发消息 |
| ParsingAndScripting | 可视化规则、发送生成、响应解析、样例回归、受限脚本契约 | 不绕过执行器自由访问设备或主机 |
| Persistence | 配置版本、实例绑定、必要运行记录及迁移 | 不在数据库回调里发设备命令 |
| Realtime | 当前状态投影、快照、增量、序号、背压与连接状态 | 不以浏览器在线人数决定设备任务生死 |
| HostMetrics | 后台主机、弦桥进程指标及有界短趋势 | 不清理磁盘、杀进程或修改系统配置 |
| WebHost | 组合服务、提供网页与内部接口、访问控制、生命周期 | 不成为包含所有协议和业务的大文件 |
| WebUI | 连接、标签、模板、定时组、调试、执行记录和主机状态视图 | 不自行重试控制，不作为后台采集循环 |
| DaWorker / ScriptWorker | 特定兼容性与隔离边界 | 不接管模板、组调度和全局产品配置 |

依赖方向建议为 WebUI／WebHost → Application → Domain；Runtime、协议、持久化等通过 Application 定义的窄接口实现用例。宿主在一个组合入口装配实现，领域规则保持可独立测试。

同一职责的代码集中在对应模块，但不为“分层”制造只有转发作用的大量文件。接口、实现、状态机、协议转换和 UI 组件应按职责分开；协议特例不能散落在网页、调度器和标签服务的条件判断中。

## 4 核心对象模型

| 对象 | 建议关键内容 | 核心约束 |
| --- | --- | --- |
| ConnectionDefinition | ConnectionId、传输种类、端口或地址、连接参数、凭据引用 | 显示名称不是物理资源身份；凭据不混入可导出模板 |
| ResourceKey | 同一物理串口或独占会话的规范化标识 | 同一端口上的多个设备必须共享执行器，不能每设备并发打开 |
| DeviceTemplateVersion | TemplateId、不可变版本、协议规则、指令、分帧、解析、脚本、标签及流程 | 发布后的版本不原地改写；变更形成新版本和差异 |
| DeviceInstance | DeviceId、ConnectionId、模板版本、设备地址和允许的覆盖参数 | 不覆盖其他实例；实际连接与通用模板分离 |
| TagDefinition | TagId、名称／别名、数据或动作类型、单位、能力、来源绑定 | 改名不改稳定标识，不能因可展示就默认可写 |
| TagSnapshot | 值、原始值、单位、质量、源时间、接收时间、版本与批次 | 保留旧值时保留旧时间；无值、坏质量、过期与合法零不同 |
| OperationPlan | 操作定义、读／写／动作／组合、输入约束、步骤、输出映射、副作用和重试声明 | 描述可重复执行的规则，本身不是一次执行结果 |
| OperationRun | RunId、调用来源、计划版本、参数快照、状态、步骤结果、时间和错误 | 一次调用一个运行身份，不用标签名当事务 ID |
| ScheduledInvocation | 调用标签及方式、计划引用、写入参数、启用状态 | 不是复制标签；参数与版本在运行前校验 |
| PeriodGroup | GroupId、Period、组状态、成员引用、配置版本 | 同组统一周期，不允许成员另藏不同周期 |
| ParseSample | 样例输入、预期输出、设备／手册信息、规则版本 | 预览与正式运行共用引擎；修改不自动接受全部新结果 |
| ExecutionEvidence | 请求、响应、阶段、关联 ID、时间、诊断、保留策略 | 已发出不等于已成功；敏感数据按规则遮盖 |

### 数据标签与动作标签

数据标签可以提供 Read、Write 中的一项或两项；动作标签提供 Invoke，参数与结果按动作定义。查看缓存统一使用 GetSnapshot，不发送设备请求。动作没有“最近测量值”时，应显示最近动作结果，不能硬塞成一个普通数值标签。

目标转速可作为可写数据标签；去皮是动作；查询重量的一条响应可以同时更新重量、单位、稳定性三个标签。通信质量与称重稳定性必须是不同字段。

## 5 统一调用契约

以下是架构级契约，不是已发布的外部 API。它服务于网页与受控脚本入口，未来开放 API 是否交付仍需确认。

| 契约 | 输入重点 | 输出与保证 |
| --- | --- | --- |
| GetSnapshot | TagId 或标签集合 | 当前已知结果与质量时间，不触发通讯 |
| ReadTag | TagId、调用来源、可选截止时间 | 接受后返回 RunId；实际执行结果独立查询或订阅 |
| WriteTag | TagId、类型正确的值、配置版本、请求身份 | 明确参数与目标；不会因 Web 重试自动重新发设备控制 |
| InvokeTag | 动作 TagId、结构化参数、配置版本、请求身份 | 执行动作绑定的计划，返回逐步状态与结果 |
| TestExchange | 连接、明确请求、分帧／解析定义 | 仍走相同资源执行器，保留测试记录，不绕过互斥 |
| PreviewTransform | 完整输入样例、规则或脚本版本 | 不访问设备的离线预览；错误位置与输出结构可检查 |
| ScheduleInvocation | 标签调用定义、周期、成员版本 | 自动创建／复用周期组，返回实际归属和变更摘要 |
| CancelRun | RunId、取消模式、发起者 | 取消请求不代表已撤销物理动作，返回恢复过程状态 |

“请求已接受”不是“设备执行成功”。Web 入口必须使用稳定请求身份防止页面重复提交；相同身份只能查询或返回同一运行，不创建第二次控制。此防重是应用入口的设计建议，不宣称分布式链路能天然做到设备端恰好执行一次。

控制参数先做类型、单位、范围和能力校验，再进入队列。CancelRun、周期组启停和连接暂停／恢复同样在服务端验证身份与控制权，不能仅凭知道 RunId 或 GroupId 就操作其他人的运行。实际发送前再次检查连接状态、配置版本及权限是否仍有效；过期或已失效请求明确拒绝，不静默使用新配置发送。

## 6 八类接口和协议的完整接入路径

| 范围 | 接入路径和能力 | 必须明确的边界 |
| --- | --- | --- |
| RS232 | SerialTransport → 设备分帧与指令计划 → 标签；单次 ASCII／HEX 测试、脚本、读取、写入和动作 | 电气接口不是业务协议；波特率、校验、停止位、流控与设备手册匹配 |
| RS422 | 共用串口传输抽象，按适配器和设备参数接入指令计划 | 不为电气差分形式虚造另一套标签引擎；双工能力依实际设备和接线验证 |
| RS485 | 串口资源执行器 → 总线设备地址 → 指令或 RTU 适配 | 半双工方向、总线共享、终端／偏置等硬件条件需现场验证，不以软件补偿不正确接线 |
| Socket | SocketTransport → 自定义分帧、关联与指令计划 → 标签 | 已确认 TCP 主动连接与被动监听接入、UDP 发送与接收监听。TCP 按字节流分帧；UDP 保留数据报边界，处理来源、丢失、重复及乱序，不套用 TCP 连接／accept 语义 |
| Modbus RTU | 共用串口执行器 → RTU 编解码、地址与 CRC → 寄存器／线圈标签 | 帧时序、共享总线、地址偏移、字节序、超时及批量边界；不假定自动识别寄存器业务含义 |
| Modbus TCP | TCP 会话 → Modbus 请求响应关联 → 寄存器／线圈标签 | 事务 ID、单元 ID、网关路由及设备并发能力；TCP 连通不等于业务请求成功 |
| OPC UA | UA 客户端会话 → 浏览／Read／Write／Method／订阅 → 标签及动作 | 保留 NodeId、命名空间 URI、质量、时间和服务端修订间隔；不是所有节点都支持所有能力 |
| OPC DA | Windows DA 适配进程 → COM/DCOM 服务器／Group／Item → 统一标签；其他平台经明确桥接接入 | DA 仍是完整需求；Linux 不承诺原生 COM/DCOM。Windows 组件位数、权限与 ARM64 支持单独验证 |

“适配器能力声明”至少表达：能否浏览、读取、写入、调用动作、订阅、取消、关联响应、批量读取，以及每项的限制。网页按真实能力展示，不显示可点击但必然不可用的控制。

OPC UA／DA 原生订阅需要保留实际采样与发布语义。用户选择周期读取时不能静默改成订阅；使用订阅监视的设计可作为单独模式，不承诺每 500 毫秒必定访问一次硬件。相关来源见 [UA 借鉴](产品借鉴/01%20通讯协议/07%20OPC%20UA%20浏览订阅与标签映射.md) 与 [DA 借鉴](产品借鉴/01%20通讯协议/08%20OPC%20DA%20Windows%20兼容与桥接.md)。

Socket 设备侧监听单独指定绑定地址、端口与允许来源，不能复用管理 Web 的开放策略。TCP 接入会话和 UDP 来源／关联分别建模，不把一个远端数据报误配到其他设备的事务；限制会话、报文与缓冲规模，禁止把重连或重收当作自动重发控制的理由。

### 平台路径必须逐项交付验证

| 后台运行目标 | 串口与网络协议路径 | OPC DA 路径 | 当前状态 |
| --- | --- | --- | --- |
| Windows x64 | 对应运行时、串口驱动及协议适配器 | 同机或 Windows 节点的 DA 适配进程 | 全部未实现、未验证 |
| Linux x64 | Linux 串口权限／驱动及协议适配器 | 连接受控 Windows DA 节点，不伪称原生 DA | 全部未实现、未验证 |
| Linux ARM64 | ARM64 驱动、原生依赖和适配器逐项验证 | 连接受控 Windows DA 节点 | 全部未实现、未验证 |
| Windows ARM64 | 运行时、驱动、依赖及供应商组件逐项验证 | 原生兼容时使用；否则评估 Windows x64 DA 节点桥接 | 全部未实现、未验证 |

Windows／Linux 及允许 Windows DA 代理已确认；表中四组合是既有交付目标，不是已获实机清单或兼容性结论。实际 OS 版本、硬件架构、驱动与 DA 服务器信息留待验证。

不支持 32 位操作系统，不自动决定是否允许在 64 位 Windows 上引入旧 32 位供应商辅助组件；若现场需要，须单独确认。不能以“最后不支持 DA”来回避这一方案评估，也不能在缺少兼容依赖时假称已解决。

## 7 通讯测试到模板复用的完整链路

1. 建连接并明确协议或手册，执行单次收发测试。测试也使用资源队列，不能与周期任务同时抢串口。
2. 选定响应分帧规则，再用可视化字段提取或脚本解析。ASCII、HEX 是显示与输入编码方式，不是两个独立业务协议。
3. 在同一预览中看原始字节、完整帧、字段、转换结果、单位、质量和错误。发送端参数生成与接收端解析使用同样的可追溯机制。
4. 把字段映射为具有稳定 ID 的标签，分别绑定读取、写入和动作计划。一个查询可输出多个标签。
5. 保存样例、预期结果和异常样例，发布模板版本。新设备选择模板后只填写实际连接与允许覆盖参数。
6. 模板升级显示版本差异、影响的标签／调用／周期成员和回归结果；用户选择实例后才应用，不全局静默更新。

建议配置编辑使用草稿与已发布版本分离。正在运行的事务固定使用开始时的计划和参数快照，不能在流程中途换解析器。新配置在安全边界应用；若连接参数改变，先暂停新调用、处理当前事务和队列，再重新连接。

可视化配置与脚本共用数据契约：输入是有界字节／参数和只读上下文，输出是有界请求字节或结构化解析结果。脚本不能直接打开串口、自由联网、访问文件或通过全局变量影响其他设备；控制仍走标签调用入口。预览不得偷偷发设备命令。

## 8 周期组和资源调度

### 8.1 周期组的产品语义

用户设置某标签读取每 500 毫秒执行，创建或复用 500 毫秒组；拖入其他标签时成员采用 500 毫秒；设置 2 秒则创建或复用 2 秒组。写入和动作同样可明确配置进组。组内不允许各成员保留不同周期。

**建议作用域**：在一个工作配置内按周期组织组，组可以引用多个连接的调用；实际执行再分发到各连接执行器。因此“同周期”不表示所有设备在同一物理瞬间完成，也不允许慢连接阻塞整个组。

建议同一个调用定义只有一个有效周期归属：从 500 毫秒改为 2 秒时显示迁移摘要，原成员移出、新组成员加入，不暗中复制出两份轮询。若读取和写入不同调用共用同一标签，可以分别配置，但需显示关联并检测竞争；跨组重复写同一目标时默认阻止启用，待用户明确解决。具体重复引用规则属于待确认设计，不能冒充已有需求。

组整体改周期时，应迁移全部成员并显示与既有目标周期组合并的结果。删除空组不删除标签或模板。暂停组停止后续到期入队，不把已发送控制当成撤回。

### 8.2 运行调度

周期调度器基于单调时间产生到期意图，记录期望时间；执行器记录入队、实际开始、发送、响应、结束时间。系统时间校正不应使周期任务突发补跑。

每个独占 ResourceKey 建一个有界队列和执行器。同一物理 RS485 端口上即使有十个 DeviceId，也只能共享这一执行器；网页、脚本、手动调试、定时组、组合流程都不能绕过它。

不同连接可以并行。网络协议即使具备请求 ID，也先以安全的每连接串行作为建议默认；只有适配器声明及实测证明并发可靠，才允许有限并发。跨连接不提供设备级原子提交。

建议同一周期成员最多保留一个运行中及有限待执行意图；若上一轮未结束，则按规则处理到期意图并记超期，不无限积压：安全读取可以折叠待执行意图；有副作用的写入／动作本轮只标跳过，不把多次执行合成一次，也不补跑历史错过的周期。具体队列上限、调度公平性和跳过策略写入后续性能验收。

### 8.3 合并读取而不改变语义

只有同连接、同查询与参数、同计划版本、同兼容到期窗口且明确无副作用的读取可以共享一次物理请求。一个重量查询更新重量、单位、稳定性时共享批次和时间，而各标签仍独立存在。

Modbus 连续地址合并还必须满足设备最大长度与无效地址边界，不跨错误寄存器随意扩展。不同周期的旧缓存不能冒充本轮读取。写入、去皮和其他动作不以“内容相同”为由合并；失败也不能把一次未知操作变成自动再发一次。

## 9 完整事务和组合流程

### 查询事务

生成查询 → 发送 → 等待完整响应 → 关联与校验 → 解析 → 更新标签批次。发送查询报文是读取的一部分，不人为拆成第二个写标签。

### 真正先写后读

校验参数 → 写入目标 → 处理应答 → 按设备规则等待 → 读取反馈 → 比较条件 → 提交逐步结果。目标和反馈可为不同标签，整轮使用一个 RunId，各步骤有独立 StepId。

单连接组合执行期间占用同一资源，普通请求不能插入中间。显式中断走下一节的恢复流程，不是假装事务已完成。每个步骤声明是否产生副作用、是否允许重试、截止时间和成功条件；写入应答成功但读回失败时保留部分结果。

组合中的等待是异步等待，不占死线程；若为了流程一致性保持串口占用，必须设总期限，避免无限等待把整个连接锁住。跨连接组合若后续确需支持，要定义部分成功和锁获取顺序，不能用本方案暗示工业设备能回滚成数据库事务。

### 状态和设备结果分开记录

| 维度 | 建议状态 | 含义 |
| --- | --- | --- |
| 运行阶段 | Accepted、Queued、Running、Cancelling、Completed | 描述软件执行进展 |
| 终态结果 | Succeeded、Failed、CancelledBeforeDispatch、OutcomeUnknown、PartiallyCompleted | 描述可证明的结果，不能只给一个“取消成功” |
| 设备证据 | NotSent、MayHaveBeenSent、Acknowledged、ReadBackMatched、PhysicalEffectConfirmed | 描述证据层次，只有实际反馈支持时才进入最后一项 |

例如，操作发送后被取消：软件可以停止后续步骤并完成取消流程，但设备结果仍可能未知。写入后反馈值匹配也不自动证明机械动作完成。平台和协议若无法提供物理反馈，就不显示最后一层成功。

## 10 中断、迟到响应与恢复

默认手动请求排在当前完整事务之后。用户选择“中断后执行”时，执行器停止尚未发送步骤，记录已发送阶段，暂停受影响的新请求，并进入恢复状态。

```text
连接就绪 → 执行完整事务 → 就绪
                  │
             超时／显式中断
                  ▼
         判定发送阶段与保留结果
                  ▼
            恢复或隔离旧响应
             │            │
         已可重新关联    无法证明安全恢复
             ▼            ▼
            就绪       等待人工恢复
```

建议连接使用软件世代标识，拒绝旧回调更新新运行；**世代不能给线上无 ID 的串口字节加标记**。对于无请求 ID 的设备，需要依据协议等待结束、隔离旧帧、重新同步，必要时关闭重开并继续等待或要求人工确认。只清一次缓冲区不能保证随后不会再到旧响应，关闭重开也不自动保证设备端停止发送。

“中断模式可用”表示系统能请求中断并安全处理，不保证任何设备都能零等待立即执行下一条。应展示恢复中及原因，不能为追求界面立即响应牺牲报文对应正确性。

读取仅在声明为安全且符合协议条件时有限重试。写入／动作若可能已发送，不自动重发；可安全读取反馈时核对，仍无证据则保留 OutcomeUnknown，由用户决定。禁止通用重试或并发竞速策略包住所有控制。

按连接暂停周期任务时，建议取消尚未开始的周期意图，保留正在执行事务默认完成；明确中断另走上述流程。恢复后从当前时间重新排程，不追赶积压写入。其他连接继续运行，软件暂停与中断都不是硬件急停。

## 11 网页实时状态与多客户端

后台状态是事实来源，网页只是投影。建议采用 HTTP 完成配置和调用请求，SignalR 推送运行状态；技术推荐详见 [03 技术方案](03%20技术方案.md)。两条通道共享身份、配置版本和请求关联规则。

### 快照加增量

- 初次打开获取当前快照及序号，再接收增量；订阅与快照切换由后台提供一致边界，避免中间漏更新。
- 增量携带流标识、单调序号、TagId／RunId、状态版本和时间；客户端检测缺口后重新取快照，不靠猜测补状态。
- 页面断线时明确标记；重连只恢复状态，不重新提交此前的 Write 或 Invoke。
- 标签值、连接状态、运行终态和原始日志分流。高频值可以合批，只保留最新投影；控制结果不能被“最新值覆盖”吞掉。
- 日志流有界，慢客户端采用截断标记与分页查询，不让浏览器背压堵住串口线程。暂停页面滚动只暂停显示，不暂停后台通讯。

设备采样时间、后台接收时间、页面更新时间分别保留；网页刷新频率不是设备采集周期。实时延迟和最大标签数等指标须由后续测试确定，不在方案中编造已达性能。

### 多浏览器与配置冲突建议

即使初期仅一个用户，也应以版本号保护配置更新：提交时携带原版本，发生冲突显示差异，不能后保存的人悄悄覆盖先前设置。运行固定快照，配置变化在安全边界生效。

本机使用不推断为单个浏览器标签页；是否允许多操作员同时控制仍未明确。推荐区分查看、配置、控制权限；对同一资源的控制仍统一排队，不允许多个网页各自直接持有驱动。操作记录保存发起身份和来源，但不据此扩大为完整企业多租户系统。

## 12 配置、执行证据和恢复

建议将连接、模板版本、实例、标签、组及样例持久化，使用应用层版本及事务保证关联一致；具体存储推荐见技术方案。原始报文与执行记录采用有界保留策略，避免变成未授权的长期数据采集仓库。

配置可以恢复，不代表控制可以自动重放。用户已接受重启后定时任务先暂停，后台重启后的恢复边界为：

1. 加载并校验配置，显示哪些依赖、端口或凭据不可用。
2. 把上次未完成且可能已发送的控制保留为未知，而不是自动从未完成步骤续跑。
3. 全部定时任务（含读取）先保持暂停，等待显式恢复；写入、动作和组合控制不得自动恢复。未来若需要安全只读自动恢复，须另行确认，当前不启用。
4. 不从日志重放历史控制，也不补齐停机期间错过的写周期。

对有副作用调用，建议在派发前保存调用意图和唯一身份，随后记录各阶段证据；证据写入失败时应拒绝尚未发送的控制，已经可能发送的则保留故障与未知。数据库事务与设备动作之间不存在天然的原子提交，不能声称加一张表就获得“设备恰好执行一次”。

已确认会导入外部模板／脚本，按不可信输入处理。导入先校验结构、版本、允许字段、引用完整性和来源，显示脚本与差异后再应用；导入本身不执行脚本、不连设备、不启用任何定时任务。启用前必须完成隔离与限制验证并获用户明确批准；批准导入不等于批准执行或设备控制。连接秘密单独引用，导出模板不能夹带密码或证书私钥。

## 13 运行主机资源监视

后台采集自身所在主机指标，经 HostMetrics 平台适配器映射为统一数据：

- 主机 CPU 使用率、内存使用与总量。
- 各网卡发送和接收速率，区分多网卡，不把累计字节显示成每秒速率。
- 各磁盘／卷容量和剩余空间，以及可获得的磁盘读写速率。容量与 I/O 不是同一个指标；物理盘与逻辑卷关联不清时明确显示层级，不能伪装逐卷 I/O。
- 弦桥进程自身 CPU 与内存，和整机指标分开。
- 有界内存环形缓冲保存短时趋势；刷新周期、窗口长度和断线后显示行为留待容量验证。

每个指标携带值、单位、采集时间、采集对象及状态。权限不足、不支持、采集失败和合法零值分开；不同平台不可用指标明确显示。采样失败不能影响设备通讯执行器，资源监视也不能反过来自动结束进程或清理磁盘。

本机网页明确显示后台主机标识与其资源。允许部署 Windows DA 代理不等于确认另监视远端 DA 节点的资源；后者仍是新范围。

## 14 进程隔离和安全边界建议

### OPC DA 适配进程

DA 进程处理供应商组件、COM 生命周期和回调，核心后台只使用统一调用与标签契约。桥接需表达 RunId、步骤、质量、时间和未知结果；断链重连不重发写入。用户已允许 Windows 代理接入 OPC DA；优先同机受控通信，必要时采用独立跨机桥接。代理通道与仅本机的 Web／API／SignalR 分开；实际拓扑、网络、身份认证、加密和现场 IT 边界仍需验证，当前不执行安装或权限变更。

这条路径保留所有平台上的系统级 DA 接入目标，但不承诺任何主机都能原生运行 DA。兼容性失败必须报告实际阻碍及替代路径，不删除需求或隐瞒缺口。

### 脚本执行边界

可视化规则与脚本支持双向转换，但脚本工作进程只接收有界输入、固定接口和截止时间。外部导入内容按不可信处理，启用须明确批准；隔离设计采用低权限独立进程、限制网络／文件能力，设置执行步数、时间、内存及输入输出大小上限，并由宿主监督退出；离线脚本预览同样受限。具体 OS 隔离机制必须实测，进程拆分本身不是完整安全沙箱。

宿主与脚本之间传递快照，不共享可变设备对象；脚本生成指令交回执行器，脚本不能自行发出控制。禁止把用户脚本直接嵌入 Web 请求线程无限执行。

### Web 和控制边界

已确认管理面仅本机回环监听，不开放局域网／公网；本机也必须验证来源、同源与防跨站请求机制，不能把任意网页请求视为控制授权。写入、动作、周期控制启用、模板更新及脚本导入需要明确操作预览和审计。对于用户明确要求的定时写入和动作，建议在启用前一次确认目标、参数、周期、允许范围和停止条件，运行时按该范围执行，不逐轮弹窗变相取消周期控制能力。目标、参数或计划发生实质变化时需要重新确认，结果未知时按策略暂停受影响控制。具体确认交互、角色和信任范围需用户集中确认，不把本节建议当已获部署授权。

## 16 实施顺序与完整交付门槛

建议先验证最容易失败的共用核心，再逐协议接入，但计划最终覆盖上表全部条目。DA 现场组件与桥接、ARM64 驱动／原生依赖、脚本隔离等高风险验证从早期并行开展，不能等到功能都写完才检查可行性：

1. 建立离线样例与模拟设备的完整标签查询链，验证模型、质量、时间及网页投影。
2. 验证周期组、资源共享、超期、先写后读、中断和未知结果，再扩大协议数量。
3. 接齐八类接口／协议，分别完成专用能力与平台路径验证，不把一个模拟串口成功当全部完成。
4. 补齐模板升级、脚本隔离、主机监视及各平台发布验证，执行所有已确认使用过程。

每一步的“完成”仅代表对应部分通过；整个产品只有在全部承诺范围有证据、未通过项清楚列出并解决后，才能称完整交付。不能以先验证版本之名永久删去 OPC DA、RS422、脚本、定时写入或其他既定需求。

## 17 已确认决策与剩余验证

两份方案共用 [03 技术方案第 13 节](03%20技术方案.md#13-已确认决策与后续验证事项) 的决策记录。原四组已答事项不再重复提问：本机网页；Windows／Linux 与允许 Windows DA 代理；重启后全部定时任务先暂停；外部模板／脚本与 Socket 全模式。具体版本、真实硬件、代理拓扑及组件兼容性尚未确认或验收，不能从通用平台回答推定。

后台重启后读取、写入和动作周期均先暂停；控制结果不确定时不重发。主机作为系统服务或开机启动，不等于允许自动恢复任务。显式恢复组时可以确认明确范围内的周期写入和动作，不需要每轮重复确认，但不得补跑历史控制。

连接数、标签数、最短周期、短趋势窗口属于需要采集的验收规模参数。组作用域、重复调用冲突、队列上限及多操作员控制权等仍是设计建议，通过后续验证收敛；若影响实际操作方式，再集中说明取舍。不会因为缺少规模数值而从最终范围删除任何已确认协议或功能。

本轮仅更新方案，不开始代码、服务部署、设备连接或权限变更。选定代理接入路径和确认产品控制功能，都不等于授权当前操作真实设备。
